# file-storage-service

Единая точка хранения бинарных файлов (фото груза/упаковки, сканы документов) поверх
S3-совместимого MinIO. См. раздел [3.4 spec.md](../../spec.md#34-file-storage-service).

Реализуется в рамках Фазы 11 (см. чек-лист в spec.md).

## Отличия от остальных сервисов

- **Нет БД и слоёв Domain/Persistence.** Всё состояние живёт в объектном хранилище, а ключ
  объекта выводится из идентификатора файла — таблица соответствий не нужна. Отсюда три
  проекта вместо пяти: `Application` (контракт), `Infrastructure` (MinIO), API.
- **Байты через сервис не проходят.** Он выдаёт presigned-ссылки, а клиент льёт и забирает
  файлы напрямую из хранилища.
- **Не участвует в обмене событиями**, поэтому не ссылается на `shared/CargoService.Contracts`.
  Контекст сборки Docker при этом всё равно корень репозитория: `Directory.Build.props` и
  `Directory.Packages.props` лежат там и нужны любому проекту.

## Команды

```
dotnet build FileStorageService.slnx
dotnet run --project FileStorageService
```
