# ai-inspection-service

Визуальная оценка целостности упаковки через ИИ. См. раздел [2.7 spec.md](../../spec.md#27-ai-inspection-service--визуальная-оценка-целостности-упаковки).

Реализуется в рамках Фазы 7 (см. чек-лист в spec.md).

Пять слоёв по общему образцу монорепозитория: `AiInspectionService.Domain` / `.Application` /
`.Persistence` / `.Infrastructure` / `AiInspectionService` (API-хост). БД и пользователь Postgres —
`aiinspectionservice`, порт для будущей записи в `docker-compose.yml` зарезервирован **8088**.

Сокращение «AI» в именах проектов и namespace записано как `Ai`, а не `AI`: так уже написаны
поля `AiDamageDetected`/`AiConfidence` в cargo-service, и разнобой в одном репозитории хуже, чем
отступление от буквы рекомендаций по именованию.

Сервис — потребитель события `CargoPhotoUploaded` и издатель `PackageIntegrityAssessed`, поэтому
у него будут и consumer, и транзакционный outbox (в отличие от notification-service, который
ничего не публикует).

## Модель

Инференс идёт **локально, через ONNX Runtime**, а не через облачный CV API: у облака нет
ни учётных данных в этом проекте, ни бесплатного режима, оно добавляет плату за вызов и
требует отправлять фото груза наружу, тогда как локальная модель работает офлайн внутри
`docker compose`. Возможность уйти в облако сохранена: инференс спрятан за интерфейсом
`IPackageInspectionModel` (Application), и внешний API станет ещё одной его реализацией.

**Контракт модели** (по нему подбирается или дообучается файл):

| | |
|---|---|
| вход | один тензор `float32[N,3,224,224]`, RGB, каналы первыми |
| нормализация | значения делятся на 255, затем ImageNet: mean `0.485/0.456/0.406`, std `0.229/0.224/0.225` |
| приведение к размеру | вписывание по меньшей стороне + кадрирование по центру (не растяжение) |
| выход | один тензор `float32[N,2]` — оценки классов в порядке `[intact, damaged]` |
| вердикт | `argmax` по двум классам; `PackagingIntegrityScore` = вероятность `intact` |

Модель, не отвечающая контракту, **отвергается при загрузке** с явным сообщением о форме —
подстраиваться под чужую форму опасно: классификатор ImageNet ничем не выдаст себя в вердикте,
кроме бессмысленных вероятностей повреждения.

Файл модели в репозиторий не кладётся (бинарь на десятки мегабайт с собственным циклом
версионирования). Путь и версия задаются конфигурацией:

```json
"AiModel": { "Path": "/models/package-integrity.onnx", "Version": "package-integrity-1.0" }
```

Пока файла нет, регистрируется `StubPackageInspectionModel`: он выводит вердикт из хэша снимка
(детерминированно, чтобы повторный прогон задания не менял результат) и на каждый вердикт пишет
предупреждение в лог. Это **не предсказание** — заглушка существует ради того, чтобы остальной
конвейер (consumer, задания, публикация события, API) оставался запускаемым и проверяемым без
модели.

Декодирование и препроцессинг снимка — на `SixLabors.ImageSharp` версии **3.1.x**: в 4.x
библиотека требует платный лицензионный ключ (сборка иначе печатает предупреждение), а 3.x
распространяется по Six Labors Split License — бесплатно для открытых проектов и небольших
компаний. Если условия перестанут подходить, замена — SkiaSharp (MIT); препроцессинг занимает
пару десятков строк в одном классе, и переписать его дешевле, чем платить за то, что здесь
используется на 1%.

## Качество модели и порог уверенности

`POST /api/inspections/evaluate` (роли `Manager`/`Admin`) прогоняет размеченный тестовый набор
через модель и отдаёт матрицу ошибок для порогов 0.5–0.95: TP/FP/TN/FN плюс precision, recall,
F1 и accuracy. Рекомендуемым считается порог с наибольшей F1 — как нейтральный ориентир; выбор
делает бизнес, потому что ложная тревога стоит рабочего времени склада, а пропущенное
повреждение — спора с клиентом, и отчёт показывает цену каждого варианта.

Набор подключается папкой:

```json
"AiModel": { "EvaluationSetPath": "/models/evalset", "DamageConfidenceThreshold": 0.7 }
```

Внутри — подпапки `damaged/` и `intact/`: разметка это имя папки, а не отдельный файл с
метками, так набор пополняется перетаскиванием снимка. В репозиторий и образ набор не кладётся
(чужие фотографии грузов), подключается томом, как и модель.

`DamageConfidenceThreshold` — порог, ниже которого вердикт «повреждено» не считается
обнаружением: с ним сводный вердикт задания (и событие `PackageIntegrityAssessed`) не поднимает
тревогу на догадке модели. Он не дублирует порог cargo-service: здесь решается, называть ли
повреждение обнаруженным, там — поднимать ли тревогу из-за расхождения с оценкой сотрудника.

## Команды

```
dotnet build AiInspectionService.slnx
dotnet run --project AiInspectionService
```

Миграции (из `AiInspectionService.Persistence/`):

```
dotnet ef migrations add <Name>
dotnet ef database update
```
